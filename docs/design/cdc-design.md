# 칠곡 중앙물류센터(칠곡 DC) 가상 현장 설계

작성 2026-11-24. 이 문서는 CDC 시뮬레이터가 그릴 센터와 작업을 정한다. 코드를 짜기 전에 여기서 정한 값만 쓴다.
수치마다 근거 태그를 단다: `[고정]` 사용자가 바꾸지 말라고 한 값, `[현장]` 실제 DC 자료(§2), `[정본]` 백엔드 업무 문서·계약, `[개념도]` 사용자 개념도(§1.3), `[가정]` 이 설계가 정한 값.

## 0. 고정값 — 절대 바꾸지 않는다 `[고정]`

| 항목 | 값 |
|---|---|
| 센터 | **칠곡 중앙물류센터 (칠곡 DC)** |
| 주소 | **경상북도 칠곡군 지천면 산단터널로 240** |
| 면적 | **8,600평** (≈ 28,430㎡, 1평 = 3.3058㎡) |

### 2.3 두 자료를 합친 작업 모델

후기의 "라인"은 기사의 **DAS**(불·숫자 보고 넣기)와 같은 작업이다. 후기의 "FC"는 **지역 바코드 기반 PDA 피킹**, "분배"는 **카트 → 지역 상자 PDA 분배**다. 셋 다 사람이 PDA·스캐너로 한다. 시뮬레이터는 이 세 작업을 사람이 하는 모습으로 그린다.

## 3. 건물과 층

### 3.1 건물 `[고정]` `[가정]`

- 칠곡 DC는 **다층 물류센터의 5~7층**을 쓴다 `[고정]`. 1층·8층은 공용(8층 휴게·흡연, 1층 출입 — 후기의 건물과 같은 구조) `[현장]`이며 8,600평에 넣지 않는다.
- 각 층에 차량이 닿는 **램프웨이(차량 경사로)와 층별 도크**가 있다고 가정한다 `[가정]`. 층 사이 물품 이동은 **화물 승강기**로 한다 `[가정]`.
- 층마다 크기가 다를 수 있다(임차 면적) `[가정]`.

### 3.2 층별 배치 `[가정]` — 확정 필요

온도대 하나를 한 층 안에 둔다(냉기 사슬을 끊지 않고, 후기처럼 한 온도대 작업자가 그 층 안에서 FC·분배·라인을 다 한다).

| 층 | 면적(평) | 보관·피킹 | 도크·분류·대기 (D/T) | 하는 일 |
|---|---:|---|---:|---|
| **5F 저온층** | 3,200 | 냉동 **F** 1,000 · 냉장 **R** 1,700 | 500 | 냉장·냉동 FC 피킹, 야채 분배, 저온 라인(DAS), 보냉 커버 롤테이너 출고대기, 저온 차량 상차 |
| **6F 상온층(박스·팔레트)** | 2,700 | 상온 **A** 1,650 (팔레트 랙, 고회전·상자존) | 1,050 | 상온 FC 피킹, 휠소터, 상온 라인(DAS), 상온 출고대기·상차 |
| **7F 상온층(낱개)** | 2,700 | 상온 **A** 1,650 (경량 선반·오토스토어, 저회전 낱개) | 1,050 | DPS 피킹, 오토스토어 포트, 박스 → 승강기로 6F 휠소터 합류 |
| 합계 | **8,600** | **6,000** (A 3,300 · R 1,700 · F 1,000) | **2,600** | |

- 구역 면적(A 3,300·R 1,700·F 1,000·D/T 2,600, 보관 6,000 / 도크 2,600)은 개념도 CDC-01 값 그대로다 `[개념도]`. 층 나눔만 이 설계의 가정이다.
- 상온은 상온 도크(6F)에서, 저온은 저온 도크(5F)에서 출고한다. 한 MFC 몫의 상온·저온 화물은 차량에서 합쳐진다(§7).

### 3.3 층 평면 `[가정]`

- 층마다 직사각형, 한쪽 긴 변에 도크(차량 접안)를 둔다. 도크 쪽 띠가 D/T, 안쪽이 보관 구역이다(CDC-01·CDC-03 그림과 같은 배치).
- 실제 좌표는 센터별 데이터 파일(`src/domain/sites/chilgok.ts`)로 둔다. 코드에 칠곡 배치를 박지 않는다(ADR-0050).

### 4.2 주소 — 계약 형식을 따른다 `[정본]`

`cdc-location-service.yaml` LocationCode: `센터-온도-구역-랙-베이-단-포지션`, 정규식 `^[A-Z0-9]+-[A-Z]-[A-Z0-9]+-[0-9]{2}-[0-9]{2}-[0-9]+-[0-9]+$`.

개념도 CDC-04 의 `A-12-24-3-1` (Zone-Aisle-Bay-Level-Slot)을 계약 형식에 이렇게 맞춘다 `[가정]`:

| 계약 필드 | 칠곡 값 | 예 |
|---|---|---|
| 센터 | 백엔드가 정한 칠곡 DC 코드 (요청 R-01, 임시 `CDC01`) | `CDC01` |
| 온도 | `A` 상온 · `R` 냉장 · `F` 냉동 (WMS 부록 2 권장, 개념도와 같음) | `A` |
| 구역 | 층 번호 (`5`·`6`·`7`) — 같은 센터에서 이 필드는 늘 층을 뜻한다(WMS 14.2.2) | `6` |
| 랙 | 통로 번호 2자리 | `12` |
| 베이 | 2자리 | `24` |
| 단 | 1~5 | `3` |
| 포지션 | 1 왼쪽 · 2 오른쪽 | `1` |

→ `CDC01-A-6-12-24-3-1`. 화면 번호판에는 개념도처럼 짧게 `A-12-24-3-1`을 쓰고, 칸 카드에는 전체 코드를 쓴다. 계약 예시가 온도 자리에 `C`를 쓰고 있어 글자 사전을 백엔드에 확인한다(R-02).

- T(TC 환적 대기)·D(PPC 출고 도크)는 랙이 아니다. 계약 locationType `STAGING`·`DOCK` 으로 두되 7구간 코드를 임의로 만들지 않는다(WMS 14.3 "확정하지 못했다면 임의로 생성하지 않는다") — 표현을 백엔드에 요청(R-03). 개념도의 `D: PPC-01 ~ PPC-30 전용 롤테이너 대기장`은 출고대기 칸의 화면 이름으로 쓴다.

### 4.3 SKU `[개념도]`

- **10,000 SKU · 150개 카테고리** `[개념도]`. 고회전 2,000 · 저회전 8,000 `[개념도 CDC-03]`.
- 1단 피킹면은 62통로 × 40 × 2 = 4,960 위치뿐이라 "1 SKU = 1위치면 10,000 SKU 전부 수용 불가"(CDC-03). → **고회전 2,000 SKU는 팔레트 랙 1단 피킹면**, **저회전 8,000 SKU는 7F 경량 선반·오토스토어(DPS) 와 저온 선반**에 둔다 `[가정]`. 기사의 DPS·오토스토어가 이 몫이다.
- 상품 이름·바코드는 시뮬레이터 가짜 마스터다(MFC 시뮬레이터처럼). 실서버 모드에서는 백엔드 SKU를 쓴다.

### 4.4 용량 520만 유닛 `[고정]`

- 팔레트 위치 목표 18,000~22,000 슬롯 `[개념도 CDC-03]` (A 12,800 + R 4,320~5,760 + F 2,880~3,840).
- 520만 ÷ 약 2만 슬롯 ≈ 슬롯당 260 유닛. T11 팔레트 한 장(예: 40박스 × 12입 = 480 유닛)에 들어가는 양이라 무리가 없다.
- 시뮬레이터는 칸마다 용량(유닛)을 주고 **모든 칸 용량 합 = 5,200,000** 이 되게 배분한다(팔레트 칸·선반 칸·오토스토어 빈 포함). 시작 재고(시드)는 이 용량의 일부를 채운다(채움률 `[가정]`, `config.ts`).
- 칸별 적격(온도·하중·혼재·예약 용량)은 WMS CDC-F-001 대로 칸마다 따로 판정한다. 센터 전체가 남는다는 이유로 칸 적격을 대신하지 않는다.

### 5.2 지역과 MFC `[개념도 dc-wave]` `[현장]`

- 후기의 바코드는 **지역 바코드**다. 지역 ≠ MFC. 한 지역에 MFC 여러 곳이 들어간다(`ref/dc-wave.md` 2-1).
- 지역으로 함께 피킹해도 MFC별 원 수량(예: 부산권 A지역 콜라 30 = 진구 10 + 동래 20)은 끝까지 유지하고, 검품·출고는 MFC별로 확정한다.
- 롤테이너(알티)에는 지역명 종이가 붙는다 `[현장]`. 라인 칸·롤테이너는 MFC(개념도의 PPC-01~30) 단위다.

### 5.3 사람과 가상 설비의 경계 `[정본]` ↔ `[현장]`

WMS 1.3 은 분류·검품·상차를 "가상 자동화 결과를 WMS 가 검증"하는 모델로 두고, 피킹만 실제 작업자로 둔다. 현장 자료는 분배·라인을 사람이 한다. 둘을 이렇게 맞춘다:

- **시뮬레이터 자체가 WMS 의 "가상 수행 모듈"이다.** 화면에서는 현장처럼 사람이 분배·라인 작업을 하고, 백엔드에는 그 결과를 `/sorting-results`·`/inspection-results`·`/loading-results` 로 보낸다.
- 백엔드에 "수동 분류 작업" 같은 새 엔드포인트를 요구하지 않는다. 계약에 없는 것은 부르지 않는다(CLAUDE.md).
- 설비 제어(컨베이어·휠소터·DAS 표시등·오토스토어 로봇)는 화면 연출일 뿐 백엔드와 주고받지 않는다.

## 7. 출고 대상과 운송

- 칠곡 DC = **영남권** 공급 `[현장 — 우아한청년들]`. 출고 대상은 영남권 MFC 다.
- MFC 목록은 백엔드 마스터를 쓴다. 지금 백엔드·MFC 시뮬레이터에 있는 MFC 는 `MFC-SEED-01`(1호점 부산)·`MFC-MOKPO-01`(목포)이다. 목포는 호남이라 칠곡 공급 대상인지 확인이 필요하다(R-04).
- MOCK 모드의 가상 MFC 는 개념도처럼 부산권(해운대·서면·동래·사하·연산·남포 등)과 대구·경북권으로 만들고, 지역 2~3곳에 묶는다 `[가정]`.
- TMS 범위(scope S-7): 차량·기사 정보, 배차, 실제 출발·도착 기록. 경로는 OR-Tools 방향 — 처음엔 지역 단위 순회, OR-Tools 는 다음 단계.
- 차량은 상온·저온 두 칸(또는 두 대)으로 두고, 5F 저온 도크와 6F 상온 도크를 차례로 들른다 `[가정]`.

## 8. 범위 `[정본 scope.md]`

- 한다: 출고·피킹·상차(+선반 보충), TMS 차량·배차·실제 출발·도착.
- 안 한다: 입고·검수(벤더 입고), 재고 조정, 품질, 수요예측, MFC 회수. 개념도의 ①벤더 입고 ②검수·적치 · TC 환적 경로는 **배경으로만** 그리고 돌리지 않는다.

## 9. 화면 — MFC 시뮬레이터 UI/UX 그대로

MFC 시뮬레이터의 화면 틀(위 막대·왼쪽 운영 조건·오른쪽 지표/상태판/로그 탭·작업자 클릭 시 PDA 화면·칸 클릭 시 로케이션 카드·밝은/어두운 테마·번호판)을 그대로 쓴다. 바뀌는 것만 적는다.

| PDA: 로케이션·상품·지시수량 | PDA: **지역 바코드**·구역·상품·수량 / 분배는 지역별 수량 / 라인은 불 색·숫자 |
