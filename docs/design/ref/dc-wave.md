# Wave(지역별 피킹패킹)**·**라인 적재(자동 선반 보충)

1. Wave: 일정한 기준에 따라 여러 피킹 작업을 묶어 관리하는 단위.
2. 지역별 피킹: PDA로 지역 바코드를 스캔해 안내된 수량만큼 상품을 스캔하고 카트에 담는 작업. 
3. 패킹: 카트에 수집된 상품을 PDA의 안내에 따라 지역별 상자에 나누어 담는 작업.
4. 라인 보충 적재: 상품 바코드를 스캔하고 표시된 라인 위치에 지정 수량을 채워 넣는 작업.
5. 입고 창고 : 피킹 선반에 바로 진열하지 않고 여분의 상품을 보관하는 DC 내부의 재고 보관 위치.
6. MOV: DC 내부에서 재고를 한 위치에서 다른 위치로 이동하도록 관리하는 문서. 보충 작업에도 사용.

Wave로 피킹 작업을 준비할 때 선반 재고가 부족한지 확인하고, 부족하면 별도의 MOV를 생성해 보충.

## 1. 개념 정의

### 1-1. 위치재고

![image.png](DC%20Wave/image.png)

| 항목 | 수량 | 의미 |
| --- | --- | --- |
| 피킹 위치 최소 재고 | 20개 | 이 수량 이하이면 보충 필요 여부를 판단 |
| 피킹 위치 목표 재고 | 80개 | 보충 후 확보하려는 수량 |
| 현재 피킹 선반 재고 | 10개 | 실제 해당 위치에 존재하는 수량 |
| 리저브 재고 | 100개 | 입고 창고에 보관된 여분 재고 |

(기존 진행 중인 보충이나 예약 재고가 없다고 가정하면)

\[
\text{보충 필요량}=80-10=70개
\]

→ 입고창고 재고에서 70개를 피킹 선반으로 이동하라는 작업번호 생성 및 작업자에게 PDA로 지시 

### 1-2. MOV 생성

MOV는 DC 내부 재고이동 작업 문서로 예를 들면 리저브에서 피킹 선반으로 옮기는 것.

재고변동시점은 출발 위치에서 재고를 차감하고 도착 위치에 재고를 증가함.

![image.png](DC%20Wave/image%201.png)

### 1-3. Wave와 선반 보충

Wave 구성과정에서 피킹에 필요한 재고가 충분한지 검사.

하나의 Wave에서 콜라 60개를 피킹해야 하는데, 피킹 선반에는 가용 재고가 10개뿐이라면

1. WMS가 Wave에 포함된 콜라 피킹 수요 60개를 확인해.
2. 피킹 선반에서 실제로 사용할 수 있는 콜라가 10개인지 검사해.
3. 부족한 50개를 확인하고 리저브에 이동 가능한 콜라가 있는지 조회해.
4. 충분하다면 MOV를 자동 생성하고 내부 보충을 지시해.
5. 보충이 완료되면 부족했던 피킹 작업을 진행할 수 있어.

따라서 두 업무의 관계는 다음과 같아.

Wave = 어떤 상품을 얼마나 피킹할지 묶어 관리

MOV = 그 상품이 피킹 위치에 부족할 경우 필요한 내부 이동을 관리

그리고 MOV는 Wave가 없어도 생성할 수 있어. 정기적으로 피킹 선반의 최소 재고를 점검해 보충하는 방식도 가능하거든.

즉, Wave 보충은 수요에 따라 발생하는 보충, 최소 재고 보충은 미리 정한 재고 기준에 따라 발생하는 보충이야.

## 2. 지역별 피킹을 기준으로 Wave 업무 다시 설계

### 2-1. 지역과 MFC를 동일하게 취급하지 않음

네가 지적한 부분이 맞아. 후기에는 지역 바코드라고 나와 있지, MFC 바코드라고 나와 있지 않아.

지역이 실제로 어떤 범위를 의미하는지는 후기만으로 알 수 없으므로 프로젝트에서는 다음처럼 구분하는 것이 적절해.

| 구분 | 의미 | 사용 목적 |
| --- | --- | --- |
| 지역(Region) | DC에서 피킹·패킹 작업을 구분하는 운영 단위 | PDA 작업 지시·분류 |
| MFC | 실제 상품을 공급받는 지역 주문처리센터 | 최종 출고 대상 식별 |
| Wave | 특정 회차·온도대·작업 구역 등에 속한 작업의 묶음 | 작업 계획·배포 |
| 피킹 작업 | 특정 지역에서 필요한 상품을 수집하는 작업 | 실제 PDA 피킹 수행 |

여기서 지역 하나에 여러 MFC가 포함될 수 있는 구조로 설계하자.

이렇게 하면 여러 MFC에 공급할 물량을 같은 지역 작업으로 묶어 처리할 수 있고, 나중에 필요한 MFC별 물량 구분도 유지할 수 있어.

단, 한 지역에 실제로 몇 개의 MFC가 연결되는지, 지역이 권역인지 세부 분류 코드인지는 현장 기준이 확인되지 않았으므로 프로젝트에서 정하는 운영 규칙이야.

### 2-2. 지역별 Wave 생성 예시

예를 들어 칠곡 DC에서 다음 물량을 처리한다고 가정해 보자.

아래 지역·MFC 배정과 수량은 실제 운영자료가 아닌 설계 예시

| 지역 작업 단위 | 포함 MFC | 콜라 필요량 |
| --- | --- | --- |
| 부산권 A지역 | 진구 10개, 동래 20개 | 30개 |
| 부산권 B지역 | 사하 15개 | 15개 |
| 합계 | 3개 MFC | 45개 |

WMS는 이를 바탕으로 하나의 Wave에 여러 지역별 피킹 작업을 포함할 수 있어.

WAVE-001

오전 출고 회차 · 상온 · 피킹 A구역

부산권 A지역

콜라 30개

피킹 작업 001

부산권 B지역

콜라 15개

피킹 작업 002

이 경우 Wave는 `WAVE-001` 하나지만 지역별 피킹 작업은 두 개야.

따라서 PDA에서 부산권 A지역 바코드를 스캔했다면 콜라 30개가, 부산권 B지역 바코드를 스캔했다면 콜라 15개가 안내될 수 있어.

### 2-3. Wave 생성 기준

| 기준 | 설계 로직 |
| --- | --- |
| 출고 회차 | 같은 출고 준비 시간대에 처리할 작업을 묶음 |
| 온도대 | 상온·냉장·냉동 작업을 구분 |
| 피킹 구역 | 작업자가 피킹할 보관 구역을 기준으로 묶음 |
| 지역 | Wave 안에 지역별 피킹 작업을 포함 |
| 피킹 수량 | 지역별 필요 SKU와 수량을 계산 |
| 작업량 | 작업자별 처리량·카트 적재량을 초과하면 작업 분할 |
| 재고 | Wave 실행 전에 피킹 가능 재고를 검사 |
| 작업 상태 | 생성·준비·실행·완료·취소 등을 관리 |

같은 Wave에 속한다고 해서 반드시 작업자 한 명이 모든 지역의 상품을 피킹하는 것은 아니야.

예를 들어 냉장 A구역 작업자와 냉장 B구역 작업자가 나누어 피킹할 수도 있고, 상품군에 따라 작업을 분리할 수도 있어.

### 2-4. Wave 생성부터 피킹까지의 흐름

| 순서 | WMS 처리 | 결과 |
| --- | --- | --- |
| 1 | 출고 대상 물량 확정 | SKU·목적지·수량 확보 |
| 2 | 작업용 지역 그룹 구성 | 지역별 필요 물량 계산 |
| 3 | Wave 생성 | 회차·온도대·구역별 작업 묶음 생성 |
| 4 | 지역·SKU별 피킹 작업 구성 | 지역 바코드에 작업 연결 |
| 5 | 피킹 위치 재고 확인 | 바로 피킹 가능한지 판단 |
| 6 | 부족한 위치의 재고 보충 필요량 계산 | 필요한 경우 MOV 생성 |
| 7 | 작업 가능한 피킹 지시 배포 | PDA에서 작업 조회 가능 |
| 8 | 작업자 피킹 진행 | 상품 스캔·수량 확인 |
| 9 | 피킹 완료 기록 | 후속 분류·집결 작업으로 전달 |

여기서 5~6번은 피킹이 원활하도록 준비하는 과정이야. Wave 자체에 선반 보충 작업이 포함되어 있다는 뜻은 아니야.

Wave와 연계해 자동으로 보충 작업을 생성하거나, 보충 완료까지 관련 피킹 작업을 대기시키는 방식은 실제 WMS에서도 지원되는 패턴이야.

## 3. 알바몬 후기 기준 DC 작업 방식 수정

### 3-1. 지역 바코드 기반 PDA 피킹

정의: 지역 바코드를 스캔하면 해당 지역 작업에 필요한 보관 구역·상품·수량이 표시되고, 작업자는 상품을 찾아 카트에 모으는 작업.

| 순서 | 작업자 행동 | WMS 비즈니스 로직 |
| --- | --- | --- |
| 1 | PDA 로그인 | 작업자 ID·DC·권한 확인 |
| 2 | 지역 바코드 스캔 | 지역 코드에 연결된 작업 조회 |
| 3 | 작업 수락 | 담당 피킹 작업 배정 |
| 4 | 보관 위치 확인 | SKU·로케이션·필요 수량 표시 |
| 5 | 피킹 위치로 이동 | 해당 작업 진행 상태 기록 |
| 6 | 상품 바코드 스캔 | 지정 상품과 실제 상품 일치 여부 확인 |
| 7 | 상품을 카트에 적재 | 피킹 수량 기록 |
| 8 | 다음 피킹 위치로 이동 | 남은 상품 순차 안내 |
| 9 | 작업 완료 | 피킹 결과 확정 및 후속 작업 연결 |

추가로 다음 검증을 포함해.

- 지정된 SKU와 스캔된 SKU가 다르면 피킹 수량에 반영하지 않음.
- 지시 수량보다 많이 피킹하려 하면 초과 수량 오류 표시.
- 피킹 가능 재고가 부족해지면 부족 수량을 기록하고 관련 작업을 보류.
- 하나의 지역 작업이 카트 적재 한도를 넘으면 피킹 작업을 여러 개로 분할.
- 같은 지역 작업을 여러 작업자가 수행할 수 있도록 피킹 작업별 배정 및 진행 수량 관리.
- 피킹 완료 시 실제 수량과 지시 수량을 비교.

지역 바코드는 어떤 지역 작업을 수행하는지 식별하고, 상품 바코드는 어떤 상품을 실제로 수집했는지 확인하는 역할이야.

### 3-2. 패킹 — 카트에 모인 상품의 지역별 분류

정의: 피킹 등의 작업으로 모인 상품을 PDA의 안내에 따라 지역별 상자로 분배 및 포장하는 작업.

| 순서 | 작업자 행동 | WMS 비즈니스 로직 |
| --- | --- | --- |
| 1 | 분배 작업 시작 | 배정된 분배 작업 조회 |
| 2 | 카트 식별 | 해당 카트의 상품·작업 정보 조회 |
| 3 | 상품 바코드 스캔 | SKU 확인 |
| 4 | PDA에서 지역별 수량 확인 | 해당 SKU의 지역별 분배 필요량 조회 |
| 5 | 안내된 지역 상자에 적재 | 실제 분배 수량 기록 |
| 6 | 지역 바코드 스캔 | 올바른 지역에 적재했는지 검증 |
| 7 | 남은 지역에도 반복 분배 | 지역별 잔여 수량 갱신 |
| 8 | 분배 완료 | 지역별 분배 결과 확정 |

예를 들어 A 지역에 필요한 야채 60개가 카트에 담겨 있으면 PDA에서 각 지역 필요량을 확인해 해당 상자에 나누어 담는 방식.

따라서 프로젝트에서는 피킹할 때부터 지역별로 구분해 담은 상품은 분배를 생략할 수 있고, 여러 지역 물량을 함께 수집한 상품은 분배 작업을 수행하도록 설계해.

### 3-3. 라인 — 스캐너 및 표시등 기반 적재

정의: 상품이 들어 있는 박스를 카트로 옮긴 뒤 상품 바코드를 스캔하고, 표시등과 숫자 안내에 맞춰 각 라인 위치에 필요한 수량을 넣는 작업.

| 순서 | 작업자 행동 | WMS 비즈니스 로직 |
| --- | --- | --- |
| 1 | 상품 박스 인수 | 작업 대상 상품 확인 |
| 2 | 박스를 카트로 이동 | 작업 대상 수량 관리 |
| 3 | 상품 바코드 스캔 | SKU 식별 |
| 4 | 지정 라인 확인 | SKU의 분류 대상 위치 조회 |
| 5 | 표시등과 수량 확인 | 각 칸에 필요한 적재 수량 안내 |
| 6 | 해당 칸에 수량대로 적재 | 적재 실적 기록 |
| 7 | 다음 칸에 반복 적재 | 잔여 수량 갱신 |
| 8 | 라인 작업 완료 | 분류 결과 확정 |

여기서 하나 정확히 구분해야 할 게 있어.

후기의 라인 작업은 물류 상품을 라인의 지정 칸에 투입하는 작업이지, 리저브 재고를 일반 피킹 선반에 보충하는 MOV 작업이라고 확정할 수 없어.

즉, 다음 두 가지는 별개야.

| 구분 | 라인 투입·적재 | 피킹 선반 보충 |
| --- | --- | --- |
| 목적 | 표시된 칸에 필요한 상품 수량 배치 | 피킹 가능 재고 부족 해결 |
| 작업 지시 | 스캐너·표시등·숫자 | MOV·보충 작업 지시 |
| 도착 위치 | 분류 또는 라인 작업 칸 | 재고 보관용 피킹 로케이션 |
| 후속 처리 | 지역별 분류·집결 | 피킹 작업 수행 |
| WMS 처리 | 라인 작업 실적·분류 수량 관리 | 재고 로케이션 이동 관리 |

라인 적재도 상품을 지정 위치에 채워 넣는다는 점에서는 넓은 의미의 투입 작업이지만, 재고 보충용 MOV와 같은 것으로 처리하지 않는 게 정확해.

## 4. DC 피킹 선반 자동 보충 비즈니스 로직

이제 Wave와 별개의 업무인 피킹 선반 보충을 설계할게.

자동 보충은 크게 두 가지 상황에서 발생할 수 있어.

| 구분 | 최소 재고 기반 보충 | Wave 수요 기반 보충 |
| --- | --- | --- |
| 발생 시점 | 정기 재고 점검 시 | Wave 피킹 준비 시 |
| 판단 기준 | 피킹 위치 재고가 최소 기준 이하 | Wave에 필요한 수량보다 피킹 가능 수량이 부족 |
| 목적 | 피킹 선반을 미리 채워 놓음 | 예정된 피킹 작업이 중단되지 않도록 준비 |
| 결과 | 필요 시 MOV 생성 | 필요 시 MOV 생성 |
| Wave 필요 여부 | 필요 없음 | 필요함 |

예를 들어 피킹 선반의 최소 재고가 20개이고 현재 25개가 있으면 최소 재고 기반 보충은 발생하지 않아.

그런데 생성된 Wave에서 40개를 피킹해야 한다면?

현재 피킹 가능한 수량은 25개뿐이므로 15개가 부족하지.

이때는 최소 재고 이하가 아니더라도 Wave 수요 기반 보충을 진행할 수 있어.

### 4-1. 보충 필요량 계산

기본적으로 다음 정보를 조회해야 해.

| 항목 | 설명 |
| --- | --- |
| SKU | 보충할 상품 |
| 현재 피킹 위치 재고 | 피킹 선반에 실제 존재하는 수량 |
| 피킹 가능 재고 | 현재 재고 중 다른 작업 예약·품질 보류 등을 제외하고 사용 가능한 수량 |
| 최소 재고 | 보충 여부 판단 기준 |
| 목표 재고 | 보충 후 확보하려는 기준 수량 |
| Wave 필요량 | 예정된 피킹 작업에서 필요한 수량 |
| 진행 중 보충량 | 이미 MOV가 생성되어 이동 예정이거나 이동 중인 수량 |
| 리저브 가용 재고 | 해당 상품을 실제로 꺼내 이동할 수 있는 수량 |
| 피킹 위치 적재 한도 | 해당 로케이션에 추가로 적재할 수 있는 최대 수량 |

최소 재고와 목표 재고는 SKU·피킹 로케이션별로 다르게 설정해야 해.

예를 들어 콜라처럼 출고가 많은 상품과 판매량이 적은 상품에 동일한 기준을 적용할 필요는 없어.

#### 최소 재고 기반 계산

보충이 필요하다고 판단되면 목표량까지 채우도록 계산해.

\[
Q_{\text{목표 보충}}=
\max(0,\text{목표 재고}-\text{현재 재고}-\text{진행 중 보충량})
\]

이것은 기존 이미지의 보충량 계산을 조금 더 명확하게 표현한 거야.

다만 실제 최종 보충량은 리저브 가용 수량, 적재 한도, 이동 단위를 고려해 결정해야 해.

#### Wave 수요 기반 계산

\[
Q_{\text{Wave 부족}}=
\max(0,\text{Wave 필요량}-\text{피킹 가능량}-\text{확정된 유입 예정량})
\]

여기서 확정된 유입 예정량은 이미 다른 계산에 반영되지 않은 진행 중 보충 수량만 포함해야 해.

즉, 현재 피킹할 수 있는 수량과 이미 보충 중인 수량으로 Wave를 처리할 수 있는지 검사하는 거야.

이후 보충 전략에 따라 필요한 부족량만큼 이동하거나, 피킹 선반 목표량까지 더 채우도록 MOV 수량을 결정할 수 있어.

프로젝트에서는 보충 수량을 목표 재고 중심으로 계산하되, Wave 수요 부족이 있으면 해당 피킹 작업을 우선 처리하는 정책을 권장해.

단, 목표 재고를 채우는 것보다 피킹 위치의 물리적 적재 한도와 출발 위치 가용 재고가 우선이야.

### 4-2. 자동 MOV 생성 조건

| 조건 | WMS 처리 |
| --- | --- |
| 피킹 위치 재고가 최소 기준 이하 | 보충 필요량 계산 |
| Wave 수요 대비 피킹 가능량 부족 | 필요한 보충량 계산 |
| 리저브에 충분한 가용 재고 존재 | 내부 MOV 생성 |
| 리저브 재고 일부만 존재 | 가능한 수량만 MOV 생성 후 잔여 부족량 기록 |
| 리저브 가용 재고 없음 | 내부 MOV 생성 불가, 재고 부족 예외 처리 |
| 동일 상품·위치에 보충이 이미 진행 중 | 진행 중 수량 반영 후 추가 필요량만 계산 |
| 보충 위치 적재 한도 초과 | 가능한 수량으로 제한하거나 작업 분할 |
| 품질·유통기한·구역 조건 부적합 | 해당 재고 또는 위치를 보충 대상으로 선택하지 않음 |

여기서 같은 SKU의 피킹 선반이 여러 개 존재할 수도 있으므로 특정 선반의 부족만 보지 않고, 해당 상품을 피킹할 수 있는 다른 적합한 위치도 함께 고려해야 해.

### 4-3. MOV 생성 예시

| 항목 | 값 |
| --- | --- |
| 이동 문서번호 | `MOV-20261020-001` |
| 이동 유형 | 내부 보충 |
| DC | 칠곡 DC |
| SKU | 콜라 500mL |
| 출발 위치 | `R01-01-101` |
| 도착 위치 | `B04-02-205` |
| 이동 수량 | 70개 |
| 생성 사유 | 피킹 선반 최소 재고 이하 |
| 연결 Wave | 해당 없음 또는 관련 Wave ID |
| 처리 상태 | 생성 |

로케이션 번호는 예시야.

MOV는 어떤 상품을 어디에서 어디로 몇 개 이동해야 하는지 기록하는 문서이고, 실제 이동 작업은 이 문서에 연결된 작업 지시로 수행하도록 하자.

### 4-4. MOV 생성 이후 PDA 작업 흐름

| 순서 | 작업자 | WMS |
| --- | --- | --- |
| 1 | — | MOV 자동 생성 |
| 2 | PDA에서 보충 작업 확인 | MOV에 연결된 작업 지시 배포 |
| 3 | 출발 로케이션으로 이동 | 출발 위치 안내 |
| 4 | 출발 위치 바코드 스캔 | 올바른 위치인지 확인 |
| 5 | 상품 바코드 스캔 | SKU 검증 |
| 6 | 지정 수량만큼 꺼냄 | 실제 이동 수량 기록 |
| 7 | 도착 피킹 선반으로 이동 | 도착 위치 안내 |
| 8 | 도착 위치 바코드 스캔 | 적합한 로케이션인지 확인 |
| 9 | 상품 적재 | 도착 수량 확인 |
| 10 | 보충 완료 | 이동 결과를 중앙 재고원장에 반영 |
| 11 | — | 대기 중이던 피킹 작업 재개 가능 여부 판단 |

상품을 꺼내고 도착 선반에 적재하기까지 재고가 이동 중인 상태를 관리해야 하므로, 작업 실패·부분 이동·중복 스캔 시에도 재고가 중복 계산되지 않도록 해야 해.

작업 취소가 발생한 경우에도 출발지 또는 이동 중 재고의 실제 상태를 확인한 후 예약과 작업을 정리해야 해.

### 4-5. 자동 보충 중 예외 상황

상황 A. 선반 부족, 리저브 충분

- 내부 MOV 자동 생성
- 리저브에서 피킹 선반으로 이동
- 보충 완료 후 피킹 진행

상황 B. 선반 부족, 리저브도 부족

- 가용 재고가 있는 다른 적합한 피킹 위치 확인
- 필요한 경우 일부 수량만 보충
- 처리 불가능한 수량은 재고 부족으로 기록
- 재고 부족을 무시하고 피킹 완료 처리하지 않음

상황 C. 선반은 충분하지만 Wave 수요가 더 큼

- Wave 수요 대비 부족량 계산
- 필요한 수량을 보충하거나 피킹 작업을 분할
- 재고가 확보된 작업부터 수행 가능하도록 관리

상황 D. 이미 동일 보충 작업 진행 중

- 진행 중인 MOV와 수량 확인
- 중복 MOV 생성 방지
- 필요한 추가 수량만 계산

상황 E. 시스템 수량과 실제 선반 수량이 다름

- 해당 위치 피킹·보충에 영향을 주는 작업 보류
- 재고 재확인 또는 실사
- 차이 수량을 검증해 재고 조정
- 수정된 가용 재고를 기준으로 보충량 재계산

## 5. 기존 이미지의 5단계를 전체 수정

기존 이미지에서 제시한 큰 구조는 유지하되, 각 단계의 의미를 정확히 바꾸면 다음과 같아.

| 단계 | 수정할 제목 | 수정된 비즈니스 로직 |
| --- | --- | --- |
| 1 | 지역별 작업을 Wave로 묶고 PDA 피킹 지시 생성 | 출고 물량을 회차·온도대·구역 기준으로 묶되, PDA 피킹은 지역 바코드 기반으로 수행. 지역과 MFC를 동일한 개념으로 취급하지 않음 |
| 2 | 피킹 가능 재고 검사 및 자동 MOV 생성 | 최소 재고 기준과 Wave 피킹 수요를 각각 검사. 부족하면 리저브에서 피킹 위치로 이동하는 MOV 생성 |
| 3 | 센터 내부 재고 보충 및 원장 관리 | 리저브 → 피킹 선반 이동, 실제 작업 완료 시 출발·도착 위치 재고 반영. 센터 전체 재고는 그대로 유지 |
| 4 | 지역별 피킹·분배·라인 적재 작업 구분 | PDA 지역 바코드 피킹, 지역별 상품 분배, 표시등 기반 라인 투입을 작업 유형별로 처리 |
| 5 | 작업 기준·위치 제약 및 출고 수량 검증 | 적합한 로케이션 우선, 품질·하중·구역 준수, 자동 보충 문서 중복 방지, 지역별 분류 수량과 최종 출고 대상 수량 일치 검증 |

기존 이미지 4번의 '센터 전체 공급 부족이면 DC→MFC TRF 검토'는 이번 범위에서 보충 판단과 구별하자. DC 전체 재고 부족은 DC 내부 MOV만으로 해결할 수 없는 별도의 공급 부족 상황이므로, 부족량을 기록하고 해당 출고 작업을 조정해야 해.

## 6. DC 전체 작업 흐름 최종안

① 출고 대상 물량 확정

SKU · 수량 · 지역별 작업 기준 · 최종 출고 대상 정보

② Wave 생성 및 피킹 작업 구성

회차 · 온도대 · 구역별 묶음과 지역별 피킹 작업

③ 피킹 위치 재고 확인

피킹 가능

피킹 작업 배포

보충 필요

리저브 조회 → MOV → 적재

재고 확보가 필요한 피킹 작업은 보충 완료까지 대기

④ 지역 바코드 기반 PDA 피킹

보관 위치 이동 → 상품 스캔 → 카트 적재

⑤ 필요한 작업 유형에 따라 분류·집결

PDA 분배

지역별 수량 안내와 지역 바코드 확인

라인 분류

상품 스캔·표시등·지정 수량 적재

작업 특성에 따라 하나 또는 필요한 작업만 수행

⑥ 지역별 집결 및 최종 출고 검수

지역·상품·수량 일치 확인 및 최종 출고 대상별 확정

여기서 지역 단위가 여러 MFC를 포함한다면, 최종 출고 수량을 확정하기 전에 해당 지역 물량을 실제 수령 MFC별로 구별할 수 있어야 해.

예를 들어 부산권 A지역으로 콜라 30개를 피킹했더라도, 진구 MFC용 10개와 동래 MFC용 20개라는 원래 수량 정보는 WMS가 계속 유지해야 해. 실제 포장 또는 적재 단위도 최종 수령처가 식별되도록 분류·검수하는 것이 이번 프로젝트의 권장 설계야.

이는 MFC별로 처음부터 별도 피킹하라는 뜻이 아니라, 지역별 공동 피킹을 지원하되 최종 출고 수량의 추적성을 유지하라는 의미야.

## 7. 시스템에 필요한 식별값과 상태값

이 비즈니스 로직을 실제 WMS에 적용하려면 문서와 작업 상태를 분리해서 관리해야 해.

### 7-1. 핵심 식별값

| 식별값 | 용도 |
| --- | --- |
| `WAVE_ID` | 피킹 작업 묶음 식별 |
| `PICK_TASK_ID` | 개별 피킹 작업 식별 |
| `REGION_ID` | 지역 작업 단위 식별 |
| `REGION_BARCODE` | PDA로 스캔하는 지역 바코드 |
| `SKU_ID` | 상품 식별 |
| `LOCATION_ID` | DC 내 보관 위치 식별 |
| `CART_ID` | 상품을 수집한 카트 식별 |
| `SORT_TASK_ID` | 지역별 분배 또는 라인 분류 작업 식별 |
| `MOV_ID` | 내부 재고 이동 문서 식별 |
| `MOVE_TASK_ID` | MOV를 수행하는 실제 이동 작업 식별 |
| `WORKER_ID` | 작업자 식별 |
| `OUTBOUND_ID` | DC 출고 대상 식별 |
| `MFC_ID` | 실제 상품을 공급받을 센터 식별 |

한 Wave에 여러 피킹 작업을 연결하고, 하나의 MOV에 필요한 이동 작업을 연결하며, 지역 작업과 최종 출고 대상의 관계는 별도로 유지하는 구조야.

### 7-2. 작업 상태

| 업무 | 권장 상태 흐름 |
| --- | --- |
| Wave | 생성 → 준비 → 실행 → 완료 |
| 피킹 작업 | 대기 → 배정 → 진행 → 완료 |
| 보충 필요 피킹 | 보충 대기 → 작업 가능 → 피킹 진행 |
| MOV | 생성 → 작업 배정 → 이동 중 → 완료 |
| 분배 작업 | 대기 → 진행 → 완료 |
| 라인 작업 | 대기 → 진행 → 완료 |
| 출고 검수 | 검수 대기 → 검수 중 → 확정 |

각 작업에는 취소·예외·부분 완료 등의 상태를 별도로 둘 수 있어.

## 8. 최종 확정할 DC 운영 원칙

| 항목 | 최종 설계 |
| --- | --- |

## 9. 기존 이미지에서 꼭 고쳐야 하는 문구

마지막으로 이미지에 있는 다섯 개의 제목과 핵심 문구를 직접 바꾸면 다음과 같아.

| 기존 이미지 문구 | 수정 문구 |
| --- | --- |
| ① Wave로 묶어 피킹하고, 목적지별로 다시 구분합니다 | ① 회차·온도대·구역별로 Wave를 구성하고, 지역 바코드 기반 피킹 작업을 생성합니다 |
| ② 피킹 위치가 최소 이하 → 시스템이 MOV 자동 생성 | ② 피킹 위치 재고가 최소 기준 이하이거나 Wave 피킹 수요에 부족하면 보충량을 계산하고 MOV를 자동 생성합니다 |
| ③ 선반 보충은 먼저 센터 안에서 리저브에서 선반으로 이동합니다 | ③ 리저브에 가용 재고가 있으면 같은 DC 내부에서 피킹 선반으로 이동하고, 완료 시 로케이션별 재고를 갱신합니다 |
| ④ 상황에 따라 보충 방법이 달라집니다 | ④ 피킹 선반 부족은 내부 MOV로 처리하고, DC 전체 재고 부족은 공급 부족 예외로 처리합니다 |
| ⑤ 기존 기준과 작업 원칙을 지킵니다 | ⑤ 자동 보충 중복 방지, 적합 로케이션 우선, 품질·하중·작업 구역 분리 원칙을 준수합니다 |

후기에서 확인한 FC·분배·라인 작업은 ①의 실제 작업 수행 흐름에 상세하게 연결하면 돼.

최종적으로 Wave는 피킹 작업을 묶는 기능, 지역 바코드는 실제 작업 대상을 식별하는 기능, MOV는 재고 이동을 지시하는 기능으로 분리하는 게 맞아.

이렇게 구성하면 기존 이미지가 설명하려던 Wave와 선반 보충의 관계를 유지하면서도, 알바몬 후기의 지역별 피킹·분배·라인 작업 방식을 반영할 수 있어. 실제 B마트의 확정 내부 규칙이 아니라, 확인된 현장 사례와 일반 WMS 작동 원리를 바탕으로 한 DC 프로젝트용 상세 비즈니스 로직이야.
